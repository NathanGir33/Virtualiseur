# Backend WHP

Bibliothèque statique (`VirtualiseurWHPBackend.lib`) qui enveloppe l'API Windows Hypervisor Platform. Elle ne requiert aucun pilote noyau développé par le projet. Le VMM ([`src/vmm`](../../vmm/README.md)) s'appuie sur elle.

## Contenu

- `WindowsHypervisorBackend` :
  - `QueryHostCapabilities()` vérifie la disponibilité de WHP.
  - `Partition` gère la partition, ses vCPU et l'émulation xAPIC de l'hyperviseur.
  - Mémoire : `AllocateAndMapGuestMemory()`, avec le suivi optionnel des pages sales, et `QueryDirtyPages()`.
  - Registres : `Get/SetVirtualProcessorRegisters()`.
  - Exécution : `RunVirtualProcessor()` et `CancelRunVirtualProcessor()` (thread-safe).
  - Interruptions : `RequestInterrupt()`, un `WHvRequestInterrupt` thread-safe.
  - `TranslateGuestVirtualAddress()`.
- `VirtualDisk` : disque brut *sparse*, ou chaîne de couches au-dessus d'un tel disque (seule la couche du dessus est écrite). Les E/S positionnelles (`OVERLAPPED`) permettent des accès concurrents depuis plusieurs threads.
- `DiskLayer` (`LayerFile`) : une couche de disque. En-tête de 4 Kio (magique `VRTLAYR1`, taille virtuelle, nom du parent dans le même dossier), puis une **table plate** de `uint64_t` (un offset par bloc de 64 Kio, 0 = bloc absent, lu dans le parent), chargée en mémoire à l'ouverture, puis les blocs ajoutés en fin de fichier. Une première écriture partielle dans un bloc absent lit les 64 Kio dans la chaîne parente, applique la modification et écrit le bloc entier (données, puis entrée de table). À l'ouverture, une entrée mal alignée ou dont le bloc dépasse la fin du fichier (écriture interrompue par un plantage) est ignorée.
- `DiskSnapshots` (`SnapshotStore`) : instantanés de disque d'une VM (sans la mémoire), pris machine éteinte ou allumée (`BeginLive` + `VirtualDisk::PushLayer`, qui bascule la couche du dessus sous un verrou lecteur/écrivain après `FlushFileBuffers`), dans `<disque>.snapshots.ini` à côté de l'image de base (réécrit de façon atomique) : chaque instantané nomme une couche figée ou l'image de base, la VM écrit dans une couche « actuelle » au-dessus. Prendre ou restaurer crée toujours une nouvelle couche actuelle vide (les couches existantes ne sont jamais réécrites). Supprimer fusionne : l'unique enfant est recopié dans la couche de l'instantané (qui prend sa place), ou, avec plusieurs enfants, les blocs de la couche sont recopiés dans chacun là où ils manquent ; chaque couche restante garde exactement la même vue et les références ne changent qu'à la fin. Refus si la VM a le disque ouvert. Utilisé par le VMM (`--snapshot`, ouverture de la couche actuelle) et compilé aussi dans le gestionnaire. **Clones liés** : le parent d'une couche peut être un chemin relatif vers le dossier d'une autre VM (jamais absolu) ; le store de la source inscrit ses clones (`[clone.<uuid>]`) et refuse de supprimer un instantané dont la couche est, ou précède, celle d'un clone ; une inscription dont le disque n'existe plus est ignorée puis effacée ; côté clone, les parcours de chaîne s'arrêtent aux couches externes. `VirtualDisk::Flatten` (clone complet) crée la cible sparse (`FSCTL_SET_SPARSE` avant de l'étendre), lit seulement les blocs alloués (tables des couches, `FSCTL_QUERY_ALLOCATED_RANGES` sur la base) et n'écrit que les blocs non nuls.
- `MachineArchive` : export / import d'une machine en un fichier `.vrtx`. En-tête (magique `VRTXMACH`, version, taille de bloc, taille virtuelle, taille de la configuration, CRC32), configuration UTF-8 et son CRC32, en version 2 la section micrologiciel (taille, CRC32 puis octets du `vars.fd` d'une machine UEFI ; taille 0 pour une machine Linux direct ou jamais démarrée ; vérifiée, bornée à 16 Mio et reconnue comme volume de firmware `_FVH` avant toute écriture, écrite seulement après le disque, supprimée en cas d'échec si l'import l'a créée ; la version 1, sans cette section, reste lue), puis un enregistrement par bloc non nul de 64 Kio `{index, taille stockée, taille réelle, drapeaux, CRC32}` : compressé XPRESS (`compressapi.h`) s'il rétrécit, sinon stocké tel quel (`ERROR_INSUFFICIENT_BUFFER` avec un tampon de sortie limité à la taille du bloc moins un) ; un enregistrement de fin donne le nombre de blocs (fichier tronqué détecté). L'export écrit `<cible>.tmp` puis le renomme. À l'import, chaque taille lue est bornée avant toute allocation (configuration ≤ 1 Mio, bloc stocké ≤ 64 Kio, index dans le disque, pas de doublon, rien après la fin) ; le disque est créé sparse (`FSCTL_SET_SPARSE` avant `SetEndOfFile`) et supprimé à la moindre erreur ou annulation. CRC32 par `RtlComputeCrc32` (ntdll).
- `Iso9660Image` : lecteur ISO 9660 (fichiers, blocs logiques de 2048 octets, libellé du volume), utilisé pour le CD-ROM virtuel et l'extraction du noyau.

Le protocole de démarrage Linux et le bus PCI sont dans le VMM (`src/vmm/boot`, `src/vmm/devices`).

Le programme consommateur doit lier `WinHvPlatform.lib`, et `WinHvEmulation.lib` s'il utilise l'émulateur d'instructions.
